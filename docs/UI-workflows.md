# Finding your way through KonMagic

The toolkit is the starting point. The persistent page bar keeps Toolkit,
Storage, Content, Structure and Review in one window. Choose a stage for the
task at hand, then return with **Toolkit** or Command-0. Back and Forward
(Command-[ and Command-]) preserve your filters, search and selections.
Opening a view does not copy or reorganize files.

**Open page in new window** (Shift-Command-N) opens the current page as an
independent view. **Window → Open another page window** opens any stage without
leaving the current page. You can keep secondary and further windows side by
side; their page bars work independently. **Main window** brings the primary
window forward. Closing an idle additional window releases its views.

Browsing state is independent between windows. Destinations, assignments,
undo and personal tag decisions share one private owner. Draft edits refresh
all windows and invalidate stale verification. A verification or copy blocks
draft assignment across all windows. Navigation can continue during a scan;
**Work continues → Show activity** returns to its page. A window with a running
scan, hash check, export, verification or copy must stay open until the work
finishes or its page's Stop control retains the partial result.

Scan comparisons and duplicate evidence open inside the current window, with
Back returning to the previous page. These detail pages also support **Open
page in new window**. Native file panels, confirmations and Quick Look retain
their standard macOS presentation. Small windows can scroll page content
rather than compressing controls into unreadable layouts.

The header explains the current stage and offers a relevant next step. Content
keeps search, scope and filters when you visit another page. Each active facet
has its own removable chip. Drilling into a treemap, connections map or tag
group offers **Back to map** or **Back to tag tree**, restoring that view and
its prior query. Switching to a map clears actions for hidden source selections.

**Browse this folder in Content** carries the inspected directory, or the
current Disk Lens focus, into the recorded-disk list. It reads the retained
ledger rather than scanning that directory again.

Destination selection stays with the window. **Edit destinations** highlights
the chosen branch; a new destination dialog lets you choose any parent or the
top level, validates names and holds duplicate siblings. Assigning sources
opens their exact-path Review while Back returns to the prior browsing page.

Review has a searchable assignment list and full selectable source and proposed
destination cards. Rename changes only the output name; Remove affects only
the draft. Before verification, folder contents remain explicitly unverified.
After verification, the page shows complete source and destination paths and
SHA-256 hashes in pages of 200 entries. Export preserves the complete verified
manifest. Verification stays in this page; **Review & copy** still opens a
separate confirmation. Empty and filtered-out drafts explain how to continue.

| Stage | Use it for | Next step |
| --- | --- | --- |
| Observe · Command-1 | Physical storage, large branches, scan changes, volume context and duplicate candidates | Open Content Explorer to review a meaningful collection |
| Discover · Command-2 | Familiar folders, retained content, semantic filters and classification corrections | Choose an explicit draft destination or edit the structure |
| Shape · Command-3 | Create, rename and reparent virtual destinations; assign individual drops or whole buckets | Review every proposed source and target |
| Review · Command-4 | Exact paths, output names, collision checks and complete-hash verification | Approve a separate verified copy only when ready |

## Choose the right view

**Disk Lens** follows physical parent folders and recorded storage weights.
Zoom into a branch to reveal small groups. Customize its view when you need
different measures, colors, packages or depth. **More tools** contains filters,
saved scans, comparison, duplicate proof, exports and volume context.

**Content Explorer** starts in Downloads. Quick places reach other familiar
folders or all retained content. The folder tree shows actual recorded folders;
the tag tree, treemap and connections show semantic groupings. Selecting a
semantic group filters observations; it does not create a physical folder.
The scope label, date and exceptions explain what each view can account for.

Metadata and retained readings are different evidence. A size match is only a
duplicate candidate. A metadata change is not a bytewise difference. Disk and
tagged catalogue counts overlap. None of these observations guarantees how
much space a removal would reclaim.

## Refine a collection you understand

Select real files or folders and choose **Refine selected tags**. Owner,
project, family, role and lifecycle describe context; they do not choose a
destination automatically. Blank fields stay unchanged. **Unassigned** clears
a category. Folder corrections apply to that exact path, so active descendants
retain their own context. Reset and correction undo affect private decisions,
not source files or original Atlas evidence.

**Collections** save a folder, search, facet intersection and visualization.
**Rules** reuse that semantic query with a destination you explicitly select.
Rules can propose output-name stem changes while retaining the extension. They
show exact pairs and held items before adding anything to the draft. Narrow a
large query: a proposal considers the first 200 matches and the draft supports
100 assignments. Rules never run unattended.

## Keep review deliberate

Drops assign individual files. Buckets preserve a whole folder's internal
hierarchy. Editing the virtual structure updates chosen destinations by stable
identity. Manual assignment remains authoritative; inference cannot relocate
it. The preview stays separate from copying.

Choose a local output folder, verify the exact preview and inspect its held
items. Copy approval rechecks current identities, complete hashes, collisions
and capacity, then records a durable receipt. Originals remain in place. Draft
undo changes the draft; it does not roll back a filesystem transfer. Original
retention is not a separately stored backup.

Contextual **Tips** explain each stage. **Welcome guide** remains available from
the toolkit. App-authored text currently uses English; native system panels
follow macOS settings.
