# Refine tags, save collections, propose rules

Your decisions are authoritative. Catalogue tags are retained evidence; personal corrections override selected semantic fields in a separate private store. They do not rewrite the catalogue, Finder tags, original contents or reading/protection evidence.

## Correct a classification

Select up to 200 exact sources and choose **Correct tags…**. Edit owner, project, family, role or lifecycle, and optionally record why. Mixed fields left empty remain unchanged. The literal choice `Unassigned` clears a selected field. Reset removes the private override; Undo restores the previous correction.

![Native personal tag correction dialog with semantic fields and explanatory note](../assets/screenshots/light-tag-corrections.png)
<figcaption>Corrections target selected paths only. Correcting a folder does not automatically cascade into its descendants.</figcaption>
</figure>

An active project can remain active under the current organization while its former venture is archived. A family celebration can be a personal memory collection even if it is stored beside downloads. Make those meanings explicit rather than trusting an extension or historical parent.

## Save a useful collection

**Collections…** saves the current bounded query and presentation: folder, search, semantic filters, view, dimension and metric. A collection is a reusable lens, not a duplicate source folder. Opening it restores the saved scope; results follow the currently connected catalogue and effective corrections. It does not freeze or verify source bytes.

</figure>

## Turn a known group into a proposal

Choose an explicit destination first, then **Rules… → New from current view…**. A rule combines a saved semantic query, a destination ID and a naming recipe. Prefix, suffix and literal replacement operate on the output filename stem while preserving the extension.

<figure markdown>
![Native proposal rule management dialog](../assets/screenshots/light-rules.png)
<figcaption>Rules run only when requested. They propose draft assignments and preserve manual decisions.</figcaption>
</figure>

<figure markdown>
![Native rule creation dialog with destination and filename recipe](../assets/screenshots/light-create-rule.png)
<figcaption>Output naming affects future copies; it does not rename the source.</figcaption>
</figure>

The exact rule proposal is bounded to the first 200 matches and 100 draft assignments. Review proposed source/destination pairs and holds before adding them to the draft. Narrow larger queries; a limited proposal is not a whole-machine apply operation. Fresh source hashes, access, collisions and capacity remain separate in Review.

Changing a draft while a rule is preparing invalidates that proposal. If you changed tags during preparation, rerun it to ensure it reflects current classifications. Automatic background sorting is not implemented.
