# From observation to deliberate organization

The five pages answer different questions. Toolkit is your overview; the four stages form a workflow, not a requirement to operate on the whole machine at once.

| Page | Question | What changes |
|---|---|---|
| Toolkit | Where should I start? | No original content |
| Storage | What occupies space and where? | Private derived scan records and view preferences |
| Content | What is this, and how should I understand it? | Optional private corrections, saved queries and proposal rules |
| Structure | Where do I want things to belong? | Virtual destinations and assignments |
| Review | What exactly will be copied, and is it safe now? | Verification prepares a plan; separately approved copying creates new output |

A file extension describes format, not purpose. Two wedding videos belong to a memory collection; a film belongs to an entertainment collection. Do not use an extension-only rule as a universal organization policy. Use semantic context and your own decisions.

An active project remains active even if an old parent venture is archived. Ownership, project identity, lifecycle and physical location are separate concepts. Change your classifications and destinations explicitly rather than moving an entire historical parent into an archive by assumption.

Start with one collection you recognize, narrow the view, refine its context, choose a destination and inspect Review. Keep broad discovery separate from bounded execution. The copy plan includes up to 100 assignments, 5,000 traversed entries and 100 GiB of logical file data.
